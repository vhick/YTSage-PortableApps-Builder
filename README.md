# YTSage PortableApps Community Builder Kit b1r1

A standalone, unofficial **PORTABLEAPPS-only** builder for
[oop7/YTSage](https://github.com/oop7/YTSage). No upstream fork, downloaded
build utilities, PAT, Windows local compiler or previous kit is required.
Uses **official, checksum-verified upstream Windows FFmpeg portable binaries**,
not a fictitious source-built native variant. Runs automatically using Windows
GitHub Actions after manual dispatch.

**Read `docs/AUDIT.md` before running** for findings and limits. Do not claim
Windows runtime success from a green CI build.

## Beginner-friendly GitHub Desktop deployment

1. On GitHub, choose **New repository** (suggested name:
   `YTSage-PortableApps-Builder`), NOT a fork of oop7/YTSage. Choose public or
   private deliberately. GitHub-hosted public repos can generally use
   Actions without charge subject to service limits; private minutes/quotas
   depend on your plan.
2. In **GitHub Desktop**, File > Clone Repository > URL or GitHub.com; choose
   the repository you just created.
3. Extract this kit ZIP into the cloned repository root. Make sure the hidden
   `.github/workflows` folder appears alongside `README.md` and `scripts`.
4. GitHub Desktop > Changes > enter a commit summary such as
   `Add YTSage PortableApps builder b1r1` > **Commit to main** > **Push origin**.
5. GitHub webpage > repository > **Actions** > choose
   **YTSage - Build PortableApps ZIP and Installer** > **Run workflow**.
   Leave `upstream_version` set to `latest` to choose latest **stable** release;
   or type a stable tag such as `v5.6.0`.
6. Watch the Actions job. Each failure names its stage. Open failed step logs;
   do not ignore a checksum, PE, installer, or publication error.
7. A successful new build has a repository **Releases** page with an
   `YTSagePortable_*_b1r1.zip`, `.paf.exe` community installer, and
   `SHA256SUMS.txt` (generated by the shared publisher). Verify both file hashes.
8. ZIP method: extract so folder is `YTSagePortable`, then double-click
   **YTSagePortable.exe** inside it. Do not open App/YTSage/YTSage.exe directly.
   Installer method: run `.paf.exe`, choose your PortableApps location, install,
   refresh the PortableApps Menu. The installer is **not** official-certified.
9. To update: CLOSE YTSage and active download helpers, copy the **entire**
   existing directory as a backup, extract new package to a fresh folder,
   copy the original **Data** folder to it. Do not overwrite Data with defaults.
10. To roll back: close processes; restore the earlier app folder and its
    matching Data backup. Review schema/absolute path compatibility first.

## Installer-only rebuild

If the main build ZIP is already published and you only need a new installer,
open **Actions > YTSage - Rebuild Installer from Validated ZIP**. Enter the exact
original managed release tag and a new revision (`r2`, `r3`...). It verifies the
existing same-repo ZIP against `SHA256SUMS.txt`, inspects its payload, creates a
new installer with the pinned Package Builder and publishes a *separate*
managed release. It does **not** compile the upstream application again. An
existing tag or checksum mismatch is not bypassed.

## Security and dependencies

- Release resolver: only stable numeric `vN.N.N` tags and official ZIP; compare
  asset SHA256 to GitHub digest or explicitly reviewed exact v5.6.0 hash.
- Source checkout: exact tag and full commit SHA are compared. Original icon,
  upstream license and pyproject identity come from that checkout.
- The builder needs GitHub's Windows hosted runner with MSVC tools and Python.
  Pillow 12.0.0 is fetched from PyPI for icon PNG generation; it is NOT shipped
  as a separate app and is not an upstream app source-build dependency.
- No self-update or elevation is required for the root launcher. The app
  intentionally may download yt-dlp/Deno on first launch. No browser credentials
  or installed-app profiles are harvested.
- The included FFmpeg is a dependency supplied by upstream; consult the
  upstream included notices and official [FFmpeg legal information](https://ffmpeg.org/legal.html).
  Redistributors must respect Qt/PySide6, FFmpeg, yt-dlp and other components'
  respective licenses, including any applicable source-offer requirements.
- The two externally referenced shared actions remain pinned to the **specified
  tags**. Their action.yml and script interfaces were reviewed, but their
  immutable commit SHAs were not independently established here; switching
  them to guessed SHAs would be less safe. Re-verify tags when auditing future
  releases and prefer trusted SHA-pinned references once confirmed.

## Runtime limitations and proof

`docs/VALIDATION.md` records exact local verification outcomes.
`docs/RUNTIME-ACCEPTANCE.md` has the real Windows GUI, notification, child,
installer and portable-data tests. The kit itself is not a compiled app; it
contains complete source/workflows to build and release on GitHub Actions.
Without an actual Windows run, none of those runtime tests is marked passed.

## Troubleshooting

- **No workflow visible:** confirm the `.github/workflows` folder was copied
  and pushed to the repository's default branch. Enable Actions in Settings.
- **GitHub 403/429:** GitHub API access or rate limiting, not 'no releases'.
  Retry after account/limit issue; do not bypass hash verification.
- **New stable release has no digest:** fails closed. Audit the release and add
  its vendor-published SHA with an exact filename/version review.
- **Unknown ZIP layout:** upstream changed packaging; update stage.py after
  inspecting the real archive. Don't guess filenames.
- **MSVC cl.exe/rc.exe missing:** choose hosted windows-latest with C++ workload.
- **Installer fails:** the verified ZIP remains staged locally in the job, but
  no partially validated Release is published. Correct the shared-action error;
  re-run, or use installer-only workflow from an already published ZIP.
- **No YouTube analysis / FFmpeg not found:** do not use YTSage's host-changing
  FFmpeg installer before investigating. Ensure bundled ffmpeg.exe and
  ffprobe.exe exist; launcher refuses to start without them.
- **Existing installed YTSage settings changed:** record ProcMon traces. Do not
  delete host directories; stop and fix only a proved app-owned write path.
- **New drive letter breaks saved location:** open YTSage Settings and select
  a current Downloads folder; keep your files backed up.
